# Milestone 3: local preview and lifecycle API

The application now has a loopback-only Go executable at `cmd/hopvista`. It binds `127.0.0.1:0` and prints its local URL. The embedded UI is intentionally minimal while visual design resources are pending. It shows start/cancel controls, lifecycle status, a direct-path caveat, and the JSON run result. This preview records `measurement_not_connected` after its placeholder run; it does not claim any DNS, route, echo, trace, or HTTP measurement.

`internal/run` owns one active diagnostic run and the latest terminal result in memory. Start snapshots the effective hop limit and sets a 60-second measurement cutoff. Cancellation and cutoff set `stopping`; a pending executor retains the busy slot until it returns and cleanup is complete. Run snapshots detach nested data so callers cannot mutate the stored evidence. Restart evicts the prior result. Findings remain absent until a completed terminal run. A failing executor produces a generic run-level error without leaking its internal message.

`internal/localapi` serves `GET /api/v1/session`, `POST /api/v1/runs`, `GET /api/v1/runs/{id}`, and `POST /api/v1/runs/{id}/cancel`. The listener Host must exactly match the actual `127.0.0.1:<port>` address. Mutations require an exact matching `Origin` and a random per-launch token in `X-HopVista-Token`. No CORS headers or URL/result logging are enabled. Start accepts absolute HTTP(S) URLs without userinfo, rejects IPv6 literals, strips fragments, and accepts hop limits 1–64 with default 30. Address-scope classification and DNS pinning were added in [milestone 4](milestone-4.md).

Tests exercise hostile/missing Origin and token, DNS-rebinding Host, method limits, invalid URL/hop input, busy/cancel/restart, immutable settings, cutoff, and a fake route held indefinitely until explicit release. That pending route test proves lifecycle ordering only; a genuinely stalled native `GetBestRoute2` remains unverified. The in-memory HTTP test transport runs in the restricted sandbox. The opt-in live loopback socket check is `HOPVISTA_LIVE_LOOPBACK=1 go test ./internal/localapi -run TestLiveLoopback` where sockets are permitted.

Verification on 2026-10-14: the root Go tests and vet passed; repeated lifecycle/API tests passed. The opt-in live loopback check passed outside the socket-restricted sandbox. The built preview executable also launched, served its UI and session token over `127.0.0.1`, and was stopped after the smoke check. Race instrumentation is still unavailable in the portable Go environment because CGO is disabled and no C compiler is installed.

This completes the local API and fake lifecycle slice of issue #10. The measurement engine, production Windows adapter, pinned HTTP, full security review, packaged executable check, and UI acceptance are still open. The empirical 250 ms allowance remains a tested-condition development policy, not a universal timing bound or release approval.
