# Milestone 7: measurement engine connected to the local API

`cmd/hopvista` now creates the production Windows IPv4 probe adapter and `internal/engine` instead of the early `measurement_not_connected` placeholder. A diagnostic run measures a pinned, direct IPv4 HTTP journey, publishes its DNS and exchange evidence, then measures the route, gateway/target echo samples, and TTL trace for the selected final host. If the HTTP journey stops before a final response but selected an IP, the trace is labeled `attempted_host`. With no selected IP, no path probe starts. The result includes an explicit unavailable IPv6 family rather than implying IPv6 was tested.

The engine preserves the run manager's 60-second cutoff and one-active-run lifecycle. It makes no native cancellation promise: a route or echo already in progress holds the busy slot until it returns and cleanup finishes. A stopping run retains completed evidence. Initial observed findings cite HTTP or DNS evidence and state direct-request limits; they do not infer a hop or network cause. The UI remains intentionally minimal pending design resources.

Fake-adapter tests exercise the HTTP-to-path handoff, final versus attempted host labeling, no selected IP, and cancellation while a fake route is pending. The pending-route test confirms that the local manager stays busy until that call returns and that no echo starts afterward. An opt-in unelevated live check on 2026-10-14 submitted a loopback HTTP target through the real local API and production adapter. It observed an HTTP 503 as a completed response, an on-link route, five target replies, a destination trace reply, and a terminal evidence-backed finding. Run with `HOPVISTA_LIVE_ENGINE=1 go test ./internal/localapi -run TestLiveEngineThroughLocalAPI -count=1 -v` outside the socket-restricted sandbox.

The current API retains its existing configurable 1–64 hop setting (default 30). Progress snapshots publish after the HTTP journey and after path sampling; finer per-hop progress and more specific finding rules are next. This local integration check does not establish packaged-executable or release acceptance. The empirical 250 ms native start margin, a genuinely stalled `GetBestRoute2`, another Windows account, and broader Windows 11 conditions remain open.
