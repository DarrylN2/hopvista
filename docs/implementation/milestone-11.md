# Milestone 11: HTTP–ICMP disagreement and pinned HTTP comparison

On 2026-10-15, a controlled engine test gave the fake adapter seven silent ICMP observations while a direct HTTP exchange returned 200. The diagnostic run completed with zero target echo replies and a trace that reached its hop limit. Its observed finding records the HTTP response and does not claim the target or path is unreachable. This checks that the two measurements remain distinct when they disagree.

The opt-in isolated executable test now makes a second diagnostic run against a loopback server through the hostname `localhost`. The application selected and connected to `127.0.0.1` and recorded HTTP 200. A separate system `curl.exe` request used `--resolve` to pin the same hostname, port, and address, disabled proxies with `--noproxy '*'`, and independently reported HTTP 200 from `127.0.0.1`. The test also confirms that starting the second run evicts the first run according to the local API lifecycle. See [the smoke-check README](../../tools/app-smoke/README.md) for reproduction commands and the [curl manual](https://curl.se/docs/manpage.html?category=23) for these option definitions.

The controlled engine test, opt-in packaged executable test, full root Go suite, and `go vet ./...` passed. The executable comparison covers the current Windows 11 x64 machine and one loopback target. It does not yet compare a Windows `tracert` result or exercise another account, broader builds and network conditions, or a genuinely stalled `GetBestRoute2` call. The 250 ms native start allowance remains empirical. Release acceptance remains open.
