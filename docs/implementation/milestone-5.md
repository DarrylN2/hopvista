# Milestone 5: pinned IPv4 HTTP measurement

`internal/httpmeasure` measures one direct IPv4 HTTP exchange per request URL, with at most three explicit redirects (four exchanges). Each exchange receives an immutable selection from `internal/target`. Its fresh `http.Transport` disables proxies and connection reuse, checks the expected hostname and port at `DialContext`, dials only the selected IPv4 literal with `tcp4`, and verifies the connected peer IP before sending HTTP. A same-host redirect reuses the pinned address. A new host is resolved and checked by the redirect policy before another exchange begins. The HTTP authority stays as the URL hostname and port.

TCP connect, TLS handshake, and time to the first response-header byte come from `httptrace` on that same HTTP exchange. The configured bounds are 2 s for TCP, 2 s for TLS, and 3 s for response headers after request writing. A missing or failed phase has no numeric duration; HTTP without TLS marks TLS skipped. The transport leaves ordinary certificate verification enabled against the URL hostname or IP identity, with hostname SNI and no IP-literal SNI. It records 3xx, 4xx and 5xx responses as HTTP responses, closes the response body promptly without downloading it, and reports a deliberately stopped redirect as a policy stop rather than a network error. A direct-path caveat remains part of the run-result contract.

In-memory fixtures check the pinned dial address, HTTP Host, actual peer verification before request writing, no connection reuse, same-host and public new-host redirects, private new-host refusal before dial, the four-exchange limit, connect failure, and response-header timeout. Opt-in live loopback HTTP/HTTPS fixtures check the real Go transport against a local server: connected peer, first-header-byte timing without waiting for a held body, 503 as a completed response, trusted hostname/SNI, wrong-name and untrusted certificate rejection, and IPv4-literal certificate verification without SNI. The live suite ran on 2026-10-14 outside the socket-restricted sandbox with `HOPVISTA_LIVE_HTTP=1 go test ./internal/httpmeasure -run TestLivePinned`.

The application preview still uses its explicit `measurement_not_connected` placeholder. The next issue #10 slice integrates the production Windows route/echo adapter; later orchestration combines this HTTP journey with DNS, route and ICMP observations under the run cutoff. Production-adapter timing, packaged executable, broader Windows conditions, UI acceptance and release acceptance remain open.
