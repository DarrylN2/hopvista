# Milestone 4: IPv4 target and redirect policy

`internal/target` now owns URL parsing, IPv4 scope classification, per-run hostname selection, and redirect decisions. The local API uses the same parser for initial targets. URLs must be absolute HTTP(S) with a valid host and port and no userinfo. IPv6 literals, including IPv4-mapped IPv6 syntax, receive `ipv6_not_supported_in_v1`. Fragments are removed because they are never sent in HTTP. Unspecified, multicast, broadcast and reserved non-destination IPv4 literals are rejected. An explicit private, loopback, link-local or other usable special-use IPv4 target is allowed.

Scope classification follows the [IANA IPv4 special-purpose registry](https://www.iana.org/assignments/iana-ipv4-special-registry/iana-ipv4-special-registry.xhtml), reviewed 2026-10-14. Private, loopback and link-local scopes are named separately. Other listed special-purpose blocks are `special_use`; an unlisted usable unicast address is `public`. This is a conservative automatic redirect policy, not a claim that every public address is reachable or every special-purpose address is unusable. The classifier does not use Go's `IsGlobalUnicast` as a public-routability test.

The selector asks for IPv4 (`ip4`) only, uses a two-second local resolver bound, records all returned A addresses in resolver order, and pins the first usable IPv4 address. It performs at most one lookup per hostname per diagnostic run. A later same-host URL reuses the selected IP even if DNS answers change. IPv6 answers are ignored in v1; a hostname without a usable A address produces `ipv4_unavailable`. The parsed URL and selected IP are read-only to callers. DNS lookup failure, DNS timeout, user cancellation, and global deadline have distinct outcomes.

Redirects are resolved explicitly against the current URL. At most three redirects may be followed, for four HTTP exchanges total. Same-host redirects reuse the pin. A new host is selected and checked before the decision exposes a permitted next selection. New-host private, loopback, link-local and special-use addresses stop with `redirect_requires_new_run`; IPv6 literals, missing IPv4, invalid URLs and the redirect limit have separate stop reasons. The decision reports the attempted URL and selected scope when available. A stop decision never exposes a `Next` value for the future HTTP module to dial.

Fixture tests cover explicit private and loopback targets, mixed A/AAAA answers, first usable A selection, changed DNS answers, same-host and relative redirects, public new-host redirects, sensitive new hosts, unavailable IPv4, unsupported IPv6, invalid URLs and credentials, cancellation, timeout, and redirect limits. They assert that stopped redirects make no new lookup where the URL or limit already rules out following. Actual HTTP connections and peer-IP verification belong to the next pinned HTTP milestone.

Release acceptance remains open. The empirical 250 ms native-call allowance, genuinely stalled `GetBestRoute2`, other Windows accounts and wider Windows 11 conditions remain unverified beyond the prior development-gate evidence.
