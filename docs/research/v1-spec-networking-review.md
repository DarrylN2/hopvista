# V1 specification networking review

Planning note for [buildable specification #10](https://github.com/DarrylN2/hopvista/issues/10). This is source-based design review, not validation of a Go implementation. Earlier evidence: [Windows probe plan](windows-v1-probes.md) and [ordinary-user IP Helper feasibility](windows-api-feasibility.md). The latter verified an unelevated Windows C# interop check, but did **not** run a Go binding or a remote IPv6 probe.

## Required specification clarifications

1. **Pin every HTTP exchange, not just a preliminary TCP check.** Resolve each URL authority under the per-family policy, choose and record a literal IP, then make the HTTP transport's `DialContext` dial only that IP and port with `tcp4` or `tcp6`. Keep the request URL authority as the intended host (including any port); this is the HTTP `Host` or HTTP/2 `:authority`. Do not replace the URL host with the chosen IP. Keep `Transport.Proxy = nil` for the agreed direct-path policy, because the default transport uses environment proxies. The dial hook must reject an unexpected authority rather than silently dial a different host. [Go request and transport docs](https://pkg.go.dev/net/http#Request), [Go transport proxy and dial fields](https://pkg.go.dev/net/http#Transport), [Go dial network/address syntax](https://pkg.go.dev/net#Dial), [Go source for the transport TLS host](https://go.dev/src/net/http/transport.go).
2. **Keep TLS identity separate from the dial IP.** For a hostname URL, verify the certificate against that hostname and send that hostname as SNI. Go's transport derives `ServerName` from the request target authority when it performs TLS; an explicit per-exchange `ServerName` is acceptable if it is the URL hostname, never the selected IP. Leave normal certificate verification enabled, record a TLS verification failure as a TLS failure, and do not retry with verification disabled. A literal IP URL is a distinct case: Go does not send an IP address as SNI; verification must be against the IP identity in the certificate, so a certificate without a matching IP SAN fails normally. Avoid `DialTLSContext` unless the implementation owns handshake and verification explicitly, since setting it bypasses the transport's `DialContext`, `TLSClientConfig`, and `TLSHandshakeTimeout` behavior. [Go TLS `ServerName` and verification](https://pkg.go.dev/crypto/tls#Config), [Go transport TLS host source](https://go.dev/src/net/http/transport.go), [Go transport dial fields](https://pkg.go.dev/net/http#Transport).
3. **Make IPv6 address formatting and scope explicit.** Parse URL host and port rather than splitting on colons; use `net.JoinHostPort` for the pinned dial address and `tcp6` for that family. Bracketed IPv6 literals and a link-local zone identifier need explicit handling. A link-local IPv6 address without a usable zone cannot generally be dialed unambiguously, so classify it as unsupported or request a scope rather than claiming an ordinary network failure. [Go URL host format](https://pkg.go.dev/net/url#URL), [Go dial and zone format](https://pkg.go.dev/net#Dial), [Go `netip.Addr` zone and address classifications](https://pkg.go.dev/net/netip#Addr).
4. **Treat redirects as fresh exchanges and trust boundaries.** Record the 3xx response and `Location`, resolve the next URL (including relative redirects), validate its scheme/authority and address policy, choose a new IP in the *same family*, and bind that exchange's HTTP dial to the new selection. Repeat even when the hostname is unchanged if the policy specifies per-exchange resolution; do not let the HTTP client follow a redirect before validation. The simplest reviewable approach is explicit one-exchange requests rather than implicit `Client` redirect following. HTTP trace hooks cover one round trip, not a redirect series. Go's default redirect handling is deliberately permissive with some headers, so v1 should send no user-supplied credentials and apply a strict per-redirect policy. [Go client redirect behavior](https://pkg.go.dev/net/http#Client), [Go HTTP trace scope](https://pkg.go.dev/net/http/httptrace#ClientTrace), [Go URL resolution](https://pkg.go.dev/net/url#URL.ResolveReference).
5. **Prevent a second DNS lookup or stale connection from defeating pinning.** A custom dialer must use the recorded literal address only. For comparable TCP/TLS/HTTP phase measurements, use a fresh transport per exchange or disable HTTP keep-alives, and close it afterward. Record whether a connection was reused via `GotConnInfo.Reused` and treat connect/TLS as absent on reuse, never zero. State whether the standalone TCP/TLS probes and HTTP exchange are separate connections; if they are, do not add their timings as if one end-to-end request. The simplest v1 design is to derive TCP and TLS phases from the pinned HTTP exchange's transport trace, with any independent TCP probe marked separately. [Go transport connection reuse](https://pkg.go.dev/net/http#Transport), [Go trace hooks and reuse status](https://pkg.go.dev/net/http/httptrace#ClientTrace).
6. **Define timing boundaries precisely.** `ConnectStart`/`ConnectDone`, `TLSHandshakeStart`/`TLSHandshakeDone`, `WroteRequest`, and `GotFirstResponseByte` can mark phases within a single HTTP round trip. `GotFirstResponseByte` is the first **response header** byte, not the first response body byte or page-rendering time. The HTTP wait should begin after `WroteRequest`, and phases lacking both endpoints should be unavailable rather than zero. `ResponseHeaderTimeout` begins after the request is fully written and does not bound response body reading. Hooks can be called concurrently or after failure; per-exchange recorders must be safe and finalized deliberately. [Go HTTP trace](https://pkg.go.dev/net/http/httptrace#ClientTrace), [Go response-header timeout](https://pkg.go.dev/net/http#Transport).
7. **State an honest cancellation/deadline contract for native calls.** Synchronous `IcmpSendEcho2` and `Icmp6SendEcho2` wait for their supplied millisecond timeout; a Go context alone cannot interrupt an in-flight native call. On cancel or the 60-second run deadline, immediately stop scheduling probes and cancel context-aware DNS/TCP/TLS/HTTP work. For each synchronous echo started before that point, bound its native timeout by the lesser of its per-probe cap and remaining run time; wait for it to return before declaring resources reusable. Preserve completed evidence and mark unfinished measurements cancelled/deadline. The 60-second cutoff is a **stop-starting-work deadline**, with at most one in-flight native-call timeout plus scheduling overhead before fully quiescent terminal status; do not promise an exact 60-second terminal response without demonstrating it. An event-based asynchronous IP Helper path is available if a stricter cancellation bound becomes required, but its buffer lifetime and completion semantics need their own validation. [Microsoft IPv4 echo](https://learn.microsoft.com/en-us/windows/win32/api/icmpapi/nf-icmpapi-icmpsendecho2), [Microsoft IPv6 echo](https://learn.microsoft.com/en-us/windows/win32/api/icmpapi/nf-icmpapi-icmp6sendecho2).
8. **Keep route evidence scoped to the selected destination.** `GetBestRoute2` finds the OS's best route for a specified destination and can return a selected source/interface/next hop. Run it for each selected destination IP rather than once per hostname. This route observation is not proof that a later TCP connection used the same path if the route changed. [Microsoft `GetBestRoute2`](https://learn.microsoft.com/en-us/windows/win32/api/netioapi/nf-netioapi-getbestroute2).

## Validation cases to add before approval

- Pinned HTTPS fixture whose DNS name resolves to two addresses: assert the chosen address is the actual TCP peer, the HTTP authority and TLS SNI remain the name, and a wrong-name or untrusted certificate fails. Include an IPv6 address and an IP-literal HTTPS URL. [Go HTTP request](https://pkg.go.dev/net/http#Request), [Go TLS config](https://pkg.go.dev/crypto/tls#Config).
- Redirect fixtures for relative, same-host, new-host, family-unavailable, loopback/private/link-local target, and repeated redirect; assert no second connection occurs until target policy and new pin are applied. Include a DNS answer that changes between resolution and HTTP to prove the dial uses the recorded literal. [Go client redirects](https://pkg.go.dev/net/http#Client), [Go URL resolution](https://pkg.go.dev/net/url#URL.ResolveReference).
- Assert a new connection per measured exchange and check `GotConnInfo.Reused == false`; test missing TCP/TLS timestamps and the first-header-byte meaning. [Go transport](https://pkg.go.dev/net/http#Transport), [Go trace](https://pkg.go.dev/net/http/httptrace#ClientTrace).
- Go-to-Windows interop fixture with a no-reply ICMP call: cancel during the call and near the global deadline; measure both when scheduling stops and when the native call drains. Exercise IPv4 and IPv6, buffer lifetime/layout, and ordinary-user execution. Remote IPv6 remains an independent acceptance gate. [Microsoft IPv4 echo](https://learn.microsoft.com/en-us/windows/win32/api/icmpapi/nf-icmpapi-icmpsendecho2), [Microsoft IPv6 echo](https://learn.microsoft.com/en-us/windows/win32/api/icmpapi/nf-icmpapi-icmp6sendecho2).

## Platform boundary

Keep the coordinator and result model free of Windows API types. A narrow platform probe interface should return normalized route, echo, and hop observations with per-measurement status and error data; the Windows adapter alone owns `GetBestRoute2`, ICMP handles, native buffers, status codes, and timeout conversion. DNS and pinned HTTP can remain shared Go code. This is an architectural recommendation supported by the different semantics of the [Windows route API](https://learn.microsoft.com/en-us/windows/win32/api/netioapi/nf-netioapi-getbestroute2) and [Go's portable network APIs](https://pkg.go.dev/net), not a claim that macOS/Linux support has been tested.
